# 3.2 调用栈与递归终止条件

## 学习目标
理解递归调用为什么会形成调用栈，能解释终止条件、递归深度和栈溢出的关系，并能检查一个递归函数是否一定会停下来。

## 核心讲解
每次函数调用都会保存自己的参数、局部变量和返回位置。递归函数连续调用自身时，这些调用会一层层压入调用栈；当最深层返回后，再按相反顺序逐层弹出并继续计算。因此，递归不是同时完成所有事情，而是先不断深入，再逐层回收结果。

终止条件是递归停止深入的出口，也叫 base case。好的终止条件必须覆盖最小规模或边界情况，并且每次递归调用都要向它靠近。递归深度表示同时存在多少层尚未返回的调用，深度过大可能导致栈溢出。

## 简短例子
阶乘 fact(3) 会先等待 fact(2)，fact(2) 等待 fact(1)，fact(1) 命中终止条件后返回，前面的调用再逐层完成乘法。

## 常见误区
不要只写递归关系而忘记终止条件；也不要让参数变化方向远离终止条件。调试递归时，应先检查最小输入是否能直接返回。

## 与后续学习的关系
理解调用栈后，才能看懂二叉树遍历、深度优先搜索和回溯搜索中的“进入”和“返回”过程。
