# 5.1 哈希表的基本思想

## 学习目标
理解哈希表为什么能提供接近 O(1) 的平均查询效率，能说清键、哈希函数、桶和存储位置之间的关系。

## 核心讲解
哈希表的核心思想是把“查找某个键”转化为“根据键直接计算位置”。哈希函数接收键，输出一个可用于定位桶的值；桶中保存与该位置相关的元素。理想情况下，不需要从头到尾扫描，只要计算一次哈希值就能快速找到目标，因此插入、删除和查询的平均复杂度常被视为 O(1)。这个效率并不是魔法，它依赖哈希函数分布较均匀、表容量合适以及冲突数量可控。

## 简短例子
统计学生学号是否出现时，可以把学号作为键存入哈希表。之后判断某个学号是否存在，只需按同样规则计算位置并检查对应桶，而不必逐个比较所有学生。

## 常见误区
常见误区是把哈希表理解成“永远 O(1)”。平均 O(1) 建立在冲突较少的前提上；如果大量键落到同一位置，查找成本会升高。

## 与后续学习的关系
本节只建立哈希表的定位思想。后续会继续讨论冲突如何产生、Set 与 Map 如何利用哈希表，以及它们在去重、计数和索引映射中的实际用途。
