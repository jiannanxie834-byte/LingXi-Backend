# 第 12 章综合项目评分 Rubric

## 1. 算法理解与正确性
- 优秀：问题建模准确，算法选择有依据，能处理正常、边界和异常样例，并能解释复杂度。
- 良好：核心算法正确，能通过主要样例，对复杂度和适用场景有基本说明。
- 合格：能完成主要功能，但边界处理或复杂度说明不够完整。
- 需改进：算法与问题不匹配，结果经常错误，无法说明核心逻辑。

## 2. 代码实现与工程结构
- 优秀：目录清晰，算法模块、输入输出、测试数据分离，README 可复现运行。
- 良好：代码结构基本清楚，运行说明较完整，主要函数职责明确。
- 合格：代码可以运行，但模块划分较弱，依赖和入口说明不够清楚。
- 需改进：代码难以运行或大量逻辑混杂，缺少必要文件和说明。

## 3. 可视化或交互体验
- 优秀：交互流程自然，关键状态展示清楚，用户能理解算法过程或训练反馈。
- 良好：能展示主要结果和部分过程，操作方式较明确。
- 合格：能看到最终输出，但过程信息较少，交互提示不足。
- 需改进：界面或输出无法支持理解，操作容易中断或误导。

## 4. 实验分析与错误处理
- 优秀：测试样例覆盖正常、边界、失败和异常输入，能分析错误原因和改进方案。
- 良好：包含多组测试样例，能说明主要结果和少量问题。
- 合格：只有基本样例，错误处理和结果分析较简略。
- 需改进：缺少测试依据，无法证明项目功能可靠。

## 5. 报告表达与项目反思
- 优秀：报告结构完整，算法、实现、测试和反思都有证据支撑，表达清楚。
- 良好：报告覆盖主要内容，能说明项目目标和实现过程。
- 合格：报告基本完整，但分析深度不足或截图说明较少。
- 需改进：报告缺项明显，无法帮助他人理解项目。
