# 7.2 图的表示：邻接矩阵与邻接表

## 学习目标
掌握邻接矩阵和邻接表两种图存储方式，能比较它们的空间复杂度和适用场景。

## 核心讲解
邻接矩阵用二维数组记录顶点之间是否有边。若有 n 个顶点，矩阵大小通常为 n × n，判断两点是否直接相连很方便，但稀疏图会浪费空间。邻接表为每个顶点保存一组相邻顶点，只存实际存在的边，更适合边数远少于 n² 的图。选择存储方式时，要看图是稠密还是稀疏，也要看操作需求：频繁判断两点是否相邻时矩阵直接，频繁遍历某个点的邻居时邻接表更自然。

## 简短例子
若有 10000 个用户但好友关系并不密集，邻接矩阵会产生巨大空表；邻接表只记录每个用户实际好友，更节省空间。

## 常见误区
不要认为邻接矩阵一定更高级。它查询单条边方便，但空间成本高。也不要在邻接表中忘记无向边需要双向加入，否则遍历时会漏掉关系。

## 与后续学习的关系
BFS 和 DFS 通常都要遍历当前顶点的邻居，因此邻接表会频繁出现。理解表示方式后，搜索代码中的 for neighbor in graph[node] 才有明确含义。存储方式选对了，后续算法实现会简洁很多。
