# 1.2 时间复杂度与大 O 表示法

## 学习目标
理解时间复杂度描述的是运行步骤随输入规模增长的趋势，能解释为什么分析时通常忽略常数项和低阶项。

## 核心讲解
时间复杂度不是精确秒数，而是估计算法执行次数与输入规模 n 的关系。不同电脑、语言和数据分布会影响实际耗时，但当 n 足够大时，增长趋势更能反映算法差异。例如一个算法大约执行 3n + 10 次基本操作，另一个大约执行 n² 次操作，随着 n 增大，后者会增长得快得多。

大 O 表示法用来描述增长趋势的上界。写成 O(n)、O(n²) 时，我们通常忽略常数项和低阶项，因为它们不会改变主导增长方式。O(3n + 10) 会简写为 O(n)，O(n² + n) 会简写为 O(n²)。

## 简短例子
遍历长度为 n 的数组并打印每个元素，大约执行 n 次主要操作，因此时间复杂度是 O(n)。如果先后遍历两次数组，主要操作约为 2n 次，仍然记为 O(n)。

## 常见误区
大 O 不是“最坏情况”的同义词。它描述增长上界；最坏、最好、平均情况是另一组分析角度。也不要把 O(n) 理解成一定比 O(log n) 慢一次固定倍数，差距会随着 n 变化。

## 与后续学习的关系
时间复杂度是比较算法方案的基础。学习查找、排序和图算法时，你会反复判断不同方案在大规模输入下的增长趋势。
