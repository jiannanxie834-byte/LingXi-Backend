# 2.2 数组：连续存储与随机访问

## 学习目标
理解数组的连续存储、下标访问和常见操作代价，能够说明数组适合哪些场景，以及为什么中间插入和删除通常比较慢。

## 核心讲解
数组把同类型或同类元素按连续位置排列，并用下标定位元素。只要知道起始位置和元素大小，就能直接计算第 i 个元素的位置，因此按下标访问通常是 O(1)。这种随机访问能力，是数组最重要的优势。

数组的代价主要出现在结构变化上。如果在中间插入元素，后面的元素往往需要整体后移；如果删除中间元素，后面的元素也需要前移补位。动态数组可以在容量不足时扩容，但扩容会复制已有元素，所以不能只看一次操作的表面代码。

## 简短例子
要频繁读取第 k 个成绩，数组很合适；如果经常在队首插入新成绩，普通数组就会产生大量移动。

## 常见误区
不要只因为数组访问快，就认为所有操作都快。下标访问快，不代表插入、删除也快；也不要忘记数组越界和容量限制。

## 与后续学习的关系
数组是排序、二分查找、动态规划表格和堆结构的基础。掌握数组的访问和移动代价，才能理解后续算法为什么选择不同结构。
