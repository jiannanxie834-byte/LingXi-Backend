# 10.2 状态定义：把问题描述成可复用的子问题

## 学习目标
理解状态定义的作用，能说明“dp[i] 表示什么”比直接套公式更重要，并能把原问题拆成可复用的子问题。

## 核心讲解
状态定义是动态规划中最关键的一步。所谓状态，就是用一个变量或一组变量描述一个子问题的答案。例如 dp[i] 可以表示爬到第 i 阶的方案数，也可以表示前 i 个物品在某容量下的最大价值；含义不同，转移方程也完全不同。好的状态定义应该足够明确，能够覆盖原问题，并且能从更小状态推导出来。写 DP 前，应先用自然语言写出状态含义，再决定数组维度和下标范围。

## 简短例子
在爬楼梯中，把 dp[i] 定义为“到达第 i 阶的不同走法数”，就能进一步思考它来自 dp[i-1] 和 dp[i-2]。如果只写 dp[i] 却不说明含义，公式就没有依据。

## 常见误区
常见错误是先写循环和数组，再反过来猜状态含义。还有人把状态定义得过大，导致转移复杂；或定义得过小，无法表达题目要求。

## 与后续学习的关系
状态定义决定转移方程、初始化和遍历顺序。后续学习背包、LCS 等案例时，每个问题首先要回答的仍然是：dp 数组中的一个格子到底代表什么。只要状态含义清楚，后面的公式、边界和代码循环都会更容易检查。
